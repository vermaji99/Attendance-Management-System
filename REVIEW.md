# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72-74) | Returns `{"status": "ok"}` without checking if MongoDB is alive. Contract requires 503 if MongoDB fails ping. | Stop MongoDB or provide bad URI; endpoint still returns 200 instead of 503. | Added `client.admin.command('ping')` inside a try/except block; return 503 with error detail on failure. |
| 2 | Module setup (lines 20-24) | No database indexes are created at startup. Fails uniqueness enforcement and causes `COLLSCAN` across queries. | Query plans use collection scans (`COLLSCAN`), and concurrent duplicate creations succeed instead of failing. | Added lifespan handler creating unique indexes on `employees.emp_code`, compound unique index on `attendance_logs.(emp_code, date)`, and compound query indexes. |
| 3 | `create_employee` (lines 78-85) | Check-then-insert race condition; lacks input validation (schema, email regex, shift start != end). `created_at` stored as naive datetime and returned as datetime object instead of epoch ms. | Send concurrent identical POST requests: both can insert duplicate records. Send invalid `shift_start == shift_end`: accepted instead of 422. | Added Pydantic schema validation (`shift_start != shift_end`, regexes); rely on unique index on `emp_code` catching `DuplicateKeyError` to return 409; set `created_at` to UTC datetime and serialize to epoch ms. |
| 4 | `list_employees` (lines 89-96) | Pagination skip bug: `skip = page * page_size`. For page 1, `skip = 20`, skipping the first 20 employees. `total` counts full collection regardless of department filter. Results are not sorted by `emp_code` asc. | Query `GET /employees?page=1`: first 20 employees are missing. Query with `?department=Sales`: `total` returns total of all employees in company. | Changed skip calculation to `(page - 1) * page_size`, filtered `total` with `count_documents(q)`, added `.sort("emp_code", 1)`, and added query validation (page >= 1, page_size 1..100). |
| 5 | `compute_late_minutes` (lines 33-37) | Inverts R2 boundary rule: `minutes = int((punch_in - start).total_seconds() / 60)` and `return minutes if minutes > 10 else 0`. For 09:40:01 on a 09:30 shift, elapsed seconds = 601, minutes = 10, so `10 > 10` evaluates to False and returns 0. Also fails on timezones and overnight shifts. | Call `compute_late_minutes` with 09:40:01: returns 0 instead of 10. | Calculated total elapsed seconds between punch-in and shift start in IST. Check `if elapsed_seconds > 600` (strictly > 10 min grace period), then return `int(elapsed_seconds // 60)`, else 0. |
| 6 | `compute_work_hours` (lines 40-42) | Uses Python's built-in `round()`, which applies Banker's rounding (round-half-to-even) instead of R4 half-up rounding. | A duration yielding 2.125 hours rounds to 2.12 instead of 2.13. | Replaced with Python `decimal.Decimal` using `ROUND_HALF_UP` quantized to `Decimal('0.01')`. |
| 7 | `compute_overtime` (lines 44-48) | Ignores R3 minimum threshold of 30 minutes; counts any minutes > 0. Does not handle overnight shifts where `shift_end` is on the next calendar day. | Punch out with 5 minutes past shift end: returns 5 instead of 0. For overnight shift (22:00-06:00), shift end is computed on shift start date instead of next day. | Enforced rule that overtime is counted only if difference >= 30 minutes; otherwise 0. For overnight shifts (`shift_end <= shift_start`), add 1 calendar day to `shift_end`. |
| 8 | `punch_in` (lines 99-105) | Unknown employee lookup (`db.employees.find_one(...)`) crashes with `TypeError: 'NoneType' object is not subscriptable` (500) when accessing `emp["shift_start"]` instead of returning 404. | `POST /attendance/punch-in` with non-existent `emp_code`: returns 500 Internal Server Error. | Explicitly check if employee exists; raise `HTTPException(404, "Employee not found")` if missing. |
| 9 | `punch_in` (lines 101-105) | Check-then-insert race condition on `attendance_logs`. Two concurrent punch-ins both pass `find_one` and create duplicate logs for the same employee and date. | Send concurrent punch-in requests simultaneously: both return 201 and insert duplicates. | Backed by unique compound index on `(emp_code, date)`; catch MongoDB `DuplicateKeyError` and return 409 Conflict. |
| 10 | `punch_in` (lines 101-104) | Naive datetime conversion and incorrect attendance date calculation (R1). Uses `datetime.fromtimestamp(...)` and `ts.date().isoformat()`, which ignores IST timezone and fails on overnight shifts where punch-in before shift end belongs to previous day. | Punch-in at 00:30 IST for an overnight shift (22:00 - 06:00) assigns the record to the current day instead of the previous day's shift. | Converted epoch ms to timezone-aware IST datetime; applied R1 rule (if `shift_end <= shift_start` and IST time `< shift_end`, date = previous calendar day); truncated milliseconds to whole seconds. |
| 11 | `punch_in` (lines 118-121) | Response exposes internal MongoDB ObjectId as `"id": str(res.inserted_id)`. Contract strictly states `_id` is internal and must not appear in responses. Also returns datetime objects instead of epoch ms integers. | Check response body: contains `"id": "..."` and ISO date string instead of epoch milliseconds integer. | Removed `"id"`, returned clean schema matching `AttendanceRecord` with epoch milliseconds for `punch_in`. |
| 12 | `punch_in` (lines 64-68) | Lacks validation for `punched_at` and `status`. `punched_at` accepts numbers below 100000000000 (seconds) or floats without 422; accepts invalid statuses like `ABSENT` or `LEAVE` which cannot be punched in. | Send `punched_at: 1700000000` (seconds) or `status: "ABSENT"`: accepted with 201 instead of 422. | Added Pydantic validator enforcing `EpochMillis` range (`100000000000 <= punched_at <= 4102444800000`) and restricted status enum to `PRESENT`, `WFH`, `ON_DUTY`. |
| 13 | `list_attendance` (lines 144-150) | In-memory loading: calls `list(db.attendance_logs.find(q))` and sorts in Python `docs.sort(...)`. At ~100k documents, this causes high memory consumption and latency. Also exposes `"id": str(d.pop("_id"))`. | Performance profiling on 100,000 records shows massive latency and memory consumption; response exposes forbidden `"id"` field. | Replaced in-memory loading with MongoDB `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)` backed by compound index; removed `"id"` injection and serialized BSON dates to epoch ms. |
| 14 | `list_attendance` (lines 127-142) | Missing date range validation: does not validate `date_from <= date_to`. Contract specifies 422 when `date_from > date_to`. | Query `GET /attendance?date_from=2026-07-10&date_to=2026-07-01`: returns empty items with 200 instead of 422. | Added validation checking `if date_from and date_to and date_from > date_to: raise HTTPException(422, "date_from cannot be greater than date_to")`. |

### Items Examined and Decided NOT to be Defects

1. **Absence of `ABSENT` / `LEAVE` creation endpoints**: Examined whether an endpoint should exist to create `ABSENT` or `LEAVE` records. Decided this is **not a defect** because the contract and `DATA_MODEL.md` explicitly state: "No endpoint creates `ABSENT` or `LEAVE` records. They exist via seeded back-office data or subsequent `PATCH` regularization."
2. **Lack of authentication/authorization in routes**: Examined whether JWT/Bearer tokens should be validated. Decided this is **not a defect** because the assignment instructions explicitly specify there is no authentication in this assignment and candidate solutions must not add unsupported authentication layers.
3. **Absence of employee deletion/update endpoints**: Examined whether `PUT`/`DELETE /employees` are missing. Decided this is **not a defect** because employee records are immutable in this specification and customer-provided `emp_code` never changes.
